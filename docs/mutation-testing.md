# Gilded Rose: mutation testing results

Mutation testing checks that the test suite would actually catch regressions.
Stryker.NET makes small changes ("mutants") to the production code, such as
`<` → `<=`, `+` → `-`, a negated condition or a removed statement, and reruns
the tests. A mutant is **killed** if at least one test fails, and **survives**
if all tests still pass.

- **Tool:** Stryker.NET 5.0.0, default mutation level (`Standard`)
- **Code under test:** commit `a0f4ea1` (refactoring complete)
- **Date:** 2026-10-03

## Run 1: full test suite

All 39 test cases, mutating the whole `GildedRose` project.

| File | Killed | Survived | Timeout | Compile error | Ignored | Score |
|---|---|---|---|---|---|---|
| `GildedRose.cs` | 34 | 0 | 0 | 3 | 6 | **100%** |
| `Program.cs` | 41 | 1 | 1 | 3 | 4 | 97.7% |
| `Item.cs` | – | – | – | – | – | no mutable logic |
| **Total** | 75 | 1 | 1 | 6 | 10 | **98.70%** (76/77) |

Mutants killed in `GildedRose.cs`: 14 comparison changes, 7 removed
statements, 7 negated conditions, 5 arithmetic changes and 1 removed block.

### Surviving mutant: accepted

`Program.cs:44`: `args.Length > 0` → `args.Length >= 0`

- **Why it survives:** the only test that calls `Program.Main` is
  `ApprovalTest.ThirtyDays`, which always passes one argument (`"30"`). With
  an argument present, both conditions take the same branch. Without one, the
  mutant would crash reading `args[0]`.
- **Decision: accepted, no test added.** `Program` is the kata's console demo,
  not the code being refactored. A test calling `Main` without arguments would
  be another console-redirecting test, which the testing strategy advises
  against. The item update rules in `GildedRose.cs` have no survivors.

### Mutants that were not tested (not gaps)

| Status | Count | Explanation |
|---|---|---|
| Compile error | 3 in `GildedRose.cs` | Stryker tried to change each `case` name to `""`. C# `case` labels must be compile-time constants, so Stryker can't switch them at runtime. Stryker can't measure these, but a changed name would fail `ItemCategory_IsMatchedByExactFullName`, the business-rule tests for that category, and the golden master. |
| Compile error | 3 in `Program.cs` | Type-invalid mutants (e.g. `string - int`). |
| Ignored | 10 | "Block already covered": Stryker skips removing a whole `{ }` block when it already mutates every statement inside it. |
| Timeout | 1 in `Program.cs` | `i++` → `i--` in the day loop creates an infinite loop. Stryker counts timeouts as detected. |

## Known blind spots of the tool

At the `Standard` level, Stryker.NET 5.0.0 did not generate any mutant for:

| Code | Why it matters | Covered by tests? |
|---|---|---|
| `item.Quality = 0;` (Backstage after the concert) | Stryker does not remove plain assignment statements, and there is no numeric-literal mutator | Yes, by construction: `BackstagePass_QualityDropsToZero_AfterConcert` expects 0 from 20 and from 50, and the golden master has every Backstage trajectory past the concert |
| Numeric literals `11`, `6`, `50`, `0`, `1` | Changing a threshold value (e.g. `11` → `12`) is not mutated, only the comparison operator | Yes: R7 rows at 11/10 and 6/5, R6 rows at 49/50, R4 rows at 0/1 sit on both sides of each value |

These are limits of the mutation tool, not survivors. They are listed so that
the 100% score is not read as "every possible change was tried".

## How to reproduce

From `csharp.xUnit/GildedRoseTests/`. `dotnet dnx` (.NET 10+) runs the tool
without installing it.

```
# Run 1: full suite
dotnet dnx dotnet-stryker --yes -- -p GildedRose.csproj

# Run 2: named tests only
dotnet dnx dotnet-stryker --yes -- -f <path>/stryker-named-only.json
```

`stryker-named-only.json` (filtering tests is only available through the
config file):

```json
{
  "stryker-config": {
    "project": "GildedRose.csproj",
    "mutate": ["**/GildedRose.cs"],
    "test-case-filter": "FullyQualifiedName!~GildedRoseTests.ApprovalTest",
    "reporters": ["cleartext", "json"]
  }
}
```

Stryker writes its reports to `StrykerOutput/` in the current directory,
which is not git-ignored. Use `-O <path>` to write them elsewhere, or delete
the folder after the run.
